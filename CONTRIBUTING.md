# Contributing

LiveVitals is tracked in Jira (project `LV`). Every change except tooling or
docs starts from a Jira issue and references its key.

## Prerequisites

- Node.js >= 24 (CI and Docker use Node 26; `.nvmrc` matches)
- npm (the lockfiles are npm-only; never edit them by hand)
- Docker, only if you want the container stack

## Setup

```bash
npm ci
npm --prefix realtime ci
cp .env.example .env.local
```

`.env.example` holds the public realtime URL. Local secrets live in untracked
`.env*` files and are never committed.

## Running

Two terminals, from the repository root:

```bash
npm run dev:realtime
npm run dev
```

Or the full stack:

```bash
docker compose up --build
```

Web app on http://localhost:3000, realtime service on http://localhost:9000.

## Checks

Run what your change touches; CI runs all of it.

```bash
npm run lint
npm run typecheck
npm test
npm run test:e2e        # Playwright, starts its own servers
npm run build
npm run test:jira       # only if scripts/jira changed
npm --prefix realtime run typecheck
npm --prefix realtime test
```

## Branches and commits

- Branch: `LV-<n>-<kebab-summary>`, off `main`.
- Commit subject: `LV-<n>: <imperative>` — for example `LV-120: Add repository hygiene files`.
- Commit body explains why the change is needed.
- One issue per pull request. Issues fixed by the same change share one PR whose
  title lists every key, e.g. `LV-31 LV-33: Fix ...`.
- The maintainer squash-merges after CI passes, then deletes the branch.

## Publishing

Maintainers publish branches through the no-mistakes gate installed on their
machine:

```bash
no-mistakes init                 # once per clone
git fetch -q origin && git rebase origin/main
git push no-mistakes LV-<n>-<kebab-summary>
```

Configuration lives in `.no-mistakes.yaml`. The gate reviews the diff, runs
lint and tests, pushes the branch and opens the pull request with the supplied
title and body. Answer any review question in the gate, then fix only findings
that keep behaviour unchanged.

External contributors fork the repository and open a normal pull request
against `main`; CI runs the same checks on it.

## Code style

- TypeScript: tabs, double quotes, semicolons. `.mjs`, `.css`, JSON, YAML and
  Markdown use two spaces. `.editorconfig` encodes this.
- `src/components/ui/` is generated by shadcn: two spaces, and changes there
  only come from `npx shadcn@latest add ... --overwrite`, never by hand.
- Reuse existing components, hooks and helpers before writing new ones. Do not
  duplicate logic across the web app and `realtime/`.
- No behaviour, route, socket-event or copy changes without the Jira issue that
  asks for them.
